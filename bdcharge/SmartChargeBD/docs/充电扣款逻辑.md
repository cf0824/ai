# 充电扣款逻辑

- 订单创建时只校验余额是否满足，但不扣款

- 订单创建时若选择的是定金额充电，还需校验（账户实际余额-充电中类型是非定金额充电订单的冻结金额和-充电中类型是定金额充电的设定金额和）是否大于即将创建订单设定金额 ——2021.11.15新增【A】（2021.11.17弃用）
- 订单创建时若选择的是定金额充电，还需校验账户实际可用余额是否大于即将创建订单设定金额，若选择其他充电模式只需判断实际可用余额是否大于0即可 ————2021.11.17 新增
- 充电中设备每次上报信息时，取已消费金额，并更新到冻结金额表（s_account_ice）
- 返回给硬件用户余额时，返回实际余额-当前冻结金额总和
- 订单结算后，订单关联的冻结金额释放（状态改为0），同时扣除用户账户实际余额，并产生一条账户交易明细

## 注

- 实际余额即s_user_info里的account字段
- 冻结总金额即s_account_ice里某user_id的所有状态为1的ice_amount和
- 冻结金额表记录的是实时冻结信息
- 每笔订单关联一条冻结信息记录
- 冻结记录状态1表示正在冻结 0表示释放冻结
- 前端显示用户余额时，后台需用账户实际余额减去当前正在冻结金额（状态为1的）总和，再展示给用户
- 结算订单时要保证不产生负值数据（如结算后余额是负数的情况）（2021.11.17弃用）
- 结算订单时可能为产生负余额的情况，是正常的（2021.11.17新增）



## 备注
### 【A】例子——2021.11.15新增 （2021.11.17弃用）
- X用户账户当前时间余额为10元
- X用户充电中订单1 类型：自动充电  设定充电金额：null 已产生金额：5元
- X用户充电中订单2 类型：定金额充电 设定充电金额：3元 已产生金额：2元

X用户进行第三笔订单下单时，计算实际可用余额为10-5-3=2元
- 此时若选择定金额充电，则设定金额不可大于2元
- 此时若选择自动充电，判断可用余额>0可正常下单
